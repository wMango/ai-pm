# P2 · Claude Code 插件：Skill + 钩子

> 配套图形版：[p2-skill.html](p2-skill.html) · 页面见 [p1-dashboard.md](p1-dashboard.md) · 引擎见 [p0-engine.md](p0-engine.md)

## 1. 交付了什么

一个 Claude Code 插件 `ai-pm`，位于 `plugin/` 目录：

| 部分 | 位置 | 作用 |
|---|---|---|
| Skill | `plugin/skills/pm/SKILL.md` | 告诉 AI 三个阶段各做什么、哪些步骤必须由人确认 |
| 钩子 | `plugin/hooks/hooks.json` | 会话开始注入项目摘要；每轮结束记录 token、刷新页面；会话结束在后台跑验收测试 |
| 命令行 | `plugin/bin/pm.mjs` | 单文件，依赖全部内联，约 600 KB，只需要 Node 20 以上 |
| 本地插件市场 | `.claude-plugin/marketplace.json` | 用于在本机安装 |

## 2. 安装

先构建命令行：

```bash
npm run build:plugin
```

在 Claude Code 里添加本地插件市场并安装（这里假设源码在 `~/ai-pm`）：

```bash
claude plugin marketplace add ~/ai-pm
```

```bash
claude plugin install ai-pm@ai-pm
```

之后在任何项目里新开会话即可生效。改了插件代码，需要重新 `npm run build:plugin`，再在会话里运行 `/reload-plugins`。

## 3. 生命周期

### 阶段一：项目开始（Skill 引导）

1. `pm init` 生成 `.pm/` 骨架。
2. AI 先和人确认 2–5 个目标，不替人编造。
3. AI 扫描仓库，起草三套架构、映射和旅程。
4. 运行 `pm dashboard` 校验，再请人确认。
5. 在 `settings.runners` 里配置本项目的测试命令。

### 阶段二：开始做一个功能（Skill 引导）

1. `pm start <id>` 声明当前模块。之后的 token 都记到这个模块上。
2. AI 起草 `.pm/acceptance/<id>.feature`（Gherkin，1–5 个场景），在聊天里和人逐条确认。
3. AI 写验收测试，先确认它是失败的。
4. 锁定（条目和测试一起锁，每个功能只需人确认一次）：
   - **功能层**：必须由人在自己的终端里运行 `pm lock <id>`，看过条目原文后按 y 确认。AI 运行这条命令一定会被拒绝，拒绝信息里附带完整命令，AI 会把它交给人。
   - **逻辑层、物理层**：AI 自查后直接运行 `pm lock <id>`。
5. 实现代码，直到验收测试通过。

### 阶段三：会话中与会话结束（钩子自动）

| 钩子 | 时机 | 做什么 | 耗时 |
|---|---|---|---|
| SessionStart | 新会话、恢复、清空、压缩后 | 输出项目摘要并注入 AI 上下文：进度、目标缺口、按杠杆排序的下一步、待复核、卡住预警、pm 命令路径 | 很快 |
| Stop | 每轮对话结束 | 把本轮新增 token 记到当前模块，刷新 `dashboard.html`，不跑测试 | 很快 |
| SessionEnd | 会话结束 | 立即返回（约 0.1 秒），启动一个独立的后台进程：记 token → 跑全部验收测试（仅当 runners 已被本机信任）→ 刷新页面，结果和失败都写进 `.pm/last-run.log` | 后台 |

SessionEnd 之所以放到后台：官方文档写明它默认只有约 1.5 秒，插件里设置的超时也抬不高，同步跑测试一定会超时。

钩子会从当前目录向上查找 `.pm/`，在子目录里打开会话也能工作。在没有 `.pm/` 的项目里，所有钩子都什么也不做，也不输出任何内容。钩子任何情况下都返回 0，不会打断会话。

## 4. 命令一览

| 命令 | 作用 |
|---|---|
| `pm init [--project 名称]` | 初始化 `.pm/`；已存在时拒绝覆盖 |
| `pm start <id>` | 声明当前模块，并提示还缺什么（条目、人确认、测试） |
| `pm lock <id...> [--by human\|ai]` | 记录验收条目、测试文件的 sha256 指纹和当时的运行命令；功能层（或指定 `--by human`）必须在终端里按 y 确认 |
| `pm trust` | 信任当前 `runners`，会话结束时才会自动运行 |
| `pm verify [--only id,id]` | 运行验收测试，写出 `evidence.json`；同时判断是否待复核 |
| `pm record --session --transcript` | 把会话 token 增量记到当前模块 |
| `pm dashboard` | 生成 `.pm/dashboard.html` |
| `pm context` | 输出给 AI 的项目摘要 |
| `pm hook <事件>` | 钩子入口，读 stdin |

## 5. `.pm/` 目录

| 文件 | 谁写 | 是否进 git |
|---|---|---|
| `pm.yaml` | 人 + AI | 是 |
| `acceptance/*.feature` | AI 起草，人或 AI 确认 | 是 |
| `locks.json` | `pm lock` | 是：锁定记录本身就是"谁确认过什么"的凭据 |
| `evidence.json` | `pm verify` | 是 |
| `ledger.jsonl` | 钩子 | 是 |
| `dashboard.html` | `pm dashboard` | 自行决定 |
| `current.json`、`last-run.log`、`trusted-runners` | 本机 | 否：`.pm/.gitignore` 已排除 |

## 6. 关键设计

### `pm.yaml` 新增字段

- `spec`：节点的验收条目文件（Gherkin）。
- `settings.runners`：按文件后缀选择测试命令，`{file}` 会被替换成加了引号的路径；后缀最长的优先匹配。
- `settings.testTimeoutSec`：单个测试的超时，默认 300 秒。
- `settings.tokenCount`：token 统计口径，见下文。

验收文件路径必须是项目内的相对路径，不能用 `..` 跳出项目。

### 状态规则补充

只有验收条目、还没有测试的节点，算"进行中"而不是"未建"，因为条目锁定就代表开工了。

### 待复核

以下任一情况，节点标为待复核：

- 从未锁定；
- 锁定后条目或测试文件被改动；
- 增加或删除了验收文件；
- 验收文件对应的运行命令变了（比如把 `bash {file}` 改成 `true {file}`，测试就会永远"通过"）；
- 功能层节点的锁不是"人在终端确认"的（被手工改过 `locks.json`，或用旧版本锁定）。

待复核是实时计算的：页面和会话上下文按当前文件判断，不用等下一次验收。人复核后重新运行 `pm lock`，标记即消失。

### Token 统计

- **按消息去重**：在本机真实会话记录里核实过，同一条回复会被拆成多行，每行重复携带同一份用量，所以必须按 `message.id` 去重。
- **默认口径**：`processed`，即新处理的 token = 输入 + 输出 + 缓存写入。
  - 原因：以本项目这次会话为例，缓存读取 4010 万，输出 28.5 万，缓存写入 67.9 万。缓存读取是每一轮重复读取上下文，计入后其他数字会被它淹没。
  - 每条流水都存了四项明细，改成 `tokenCount: all` 即可把缓存读取也计入。
- **增量记录**：用会话累计用量减去这个会话已经记录的量。同一会话中途 `pm start` 切换模块，之后的增量自然记到新模块。
- **未归属**：没有声明模块时，token 记到保留 id `unassigned` 下，页面上单独显示。
- **格式风险**：会话记录的格式是 Claude Code 的内部格式，官方说明它可能变化。解析写得很宽容：读不到就记 0 并给出警告，不会报错。

## 7. 安全

- **测试文件路径**：
  - 路径通过环境变量传给 shell，以 `"$PM_FILE"` 引用，展开后不会再被解释。即使模板写成 `bash "{file}"` 或 `bash '{file}'`，路径里的 `$()`、反引号、单引号也无法注入（三种模板都有测试）。
  - 路径不能以 `-` 开头，也不能含控制字符。
- **测试命令本身（runners 信任）**：
  - `settings.runners` 属于项目配置。手动运行 `pm verify` 时照常执行。
  - 会话结束的后台验收是无人值守的，所以只在本机信任过当前 runners 时才执行：`pm init` 自动信任自己生成的配置；之后 runners 被改动，或者是新克隆的仓库，都要先运行 `pm trust`。
  - 信任记录只存在本机，不进 git。
- **会话上下文**：注入给 AI 的项目数据会压平换行、去掉 `#` 和反引号、截断长名字，并用 `<project-data>` 围起来，声明"是数据，不是指令"。SKILL.md 里也写明了这一点。
- **并发**：记账整段加跨进程锁，避免 Stop 钩子和后台进程同时记账造成重复计数；文件先写临时文件再改名，不会读到写了一半的内容。
- **验收生命周期**：`.verify.lock` 记录持有者 PID，已有验收时跳过重复启动，退出后遗留的锁可恢复；同轮共享测试文件只执行一次。子进程带 `AI_PM_VERIFY_ROOT`，禁止同项目递归验收和钩子。独立监督进程在测试完成、超时、收到终止信号或验收父进程消失时，清理测试所属的 POSIX 进程组。
- **终端输出**：去掉控制字符。
- **页面**：沿用 P1 的转义与 CSP。

### 代码审查

独立安全审查发现 2 个 HIGH、8 个 MEDIUM、6 个 LOW。已修复：

| 级别 | 问题 | 处理 |
|---|---|---|
| HIGH | 模板给 `{file}` 加引号时，单引号转义失效，可以注入 | 改为环境变量传参，三种模板都有测试 |
| HIGH | 改 runner 命令（如改成 `true`）不会触发待复核 | 锁定时同时记录运行命令 |
| MEDIUM | 陌生仓库或第三方改的 runners 会在会话结束时被自动执行 | 本机信任机制（`pm trust`） |
| MEDIUM | 两个会话同时结束，载荷文件互相覆盖 | 改为管道传给后台进程 |
| MEDIUM | Stop 与后台进程并发记账，造成重复计数 | 跨进程锁 |
| MEDIUM | 并发写 `evidence.json`，读到半截文件 | 原子写 |
| MEDIUM | 待复核要等下一次验收才显示 | 实时计算 |
| MEDIUM | 在子目录打开会话时钩子不工作 | 从事件 `cwd` 向上查找；仅在未提供 `cwd` 时回退到 `CLAUDE_PROJECT_DIR` |
| MEDIUM | 名字里带换行，可以伪造上下文里的"指令" | 压平换行、加围栏、在 Skill 里声明 |
| MEDIUM | "人确认"只是一个参数，AI 可以代劳 | 改为人在终端里按 y 确认（见下） |
| LOW | 后台进程失败无人知晓 | 失败写进 `last-run.log` |
| LOW | 路径以 `-` 开头，会变成命令行参数注入 | schema 拒绝 |
| LOW | 重复的验收文件导致节点永远待复核 | 去重 |
| LOW | 一行坏流水拖垮页面 | 跳过坏行并警告 |
| LOW | 插件目录是软链时命令静默不执行 | 比较真实路径 |
| LOW | 后台进程启动失败抛出未捕获异常 | 加错误处理 |

### 功能层锁定：人在终端里亲手确认（2026-10-26 决定）

- **判断"人在终端前"**：标准输入和标准输出都连着真实终端，才算人在终端前。以下情况都不成立，一律拒绝：
  - AI 通过 Bash 工具运行；
  - 用 `echo y |` 往管道里喂答案；
  - 在 Claude Code 里用 `!` 执行命令。
- **确认过程**：
  - 回答从 `/dev/tty` 读取，不读标准输入，所以管道喂不进去；
  - 终端里会显示完整的验收条目原文和测试文件列表；
  - 只有输入 `y` 或 `yes` 才锁定，其他任何输入都算取消。
- **全有或全无**：一次锁定多个节点时，只要有一个需要人确认而当前没有人，整条命令都不执行。
- **锁定记录**：标记为 `by: human, confirmedVia: terminal`。功能层节点的锁缺少这个标记，就显示为待复核。
- **已验证**：用打包后的命令行实测了四种情况：AI 运行 → 拒绝；管道喂 y → 拒绝；伪终端里人输入 n → 取消；人输入 y → 锁定，之后验收不再待复核。
- **边界**：这能挡住 AI 正常操作时的代劳，但不是密码学意义上的保证。蓄意伪造终端（`script`、`expect`）或直接改写 `locks.json` 仍然做得到。Skill 明确禁止这样做；团队场景建议再用 CODEOWNERS 保护 `locks.json`。

没有修、已写入局限的：
- **测试引用的辅助文件**（fixtures、helpers）改了，不会触发待复核。
- **测试自行脱离进程组**的后台服务仍需测试自己关闭；监督进程仅清理测试所属进程组。
- **同一项目同时开多个会话**时，`current.json` 是共用的，token 可能记到别的会话声明的模块上。

## 8. 测试

共 129 个测试，类型检查通过。P2 新增 53 个：

- **初始化、开工、锁定（10 个）**：生成合法骨架、不覆盖已有文件、提示缺什么、功能层必须由人锁定、缺文件拒绝锁定。
- **验收（11 个）**：
  - 运行并汇总结果；
  - 待复核的四种情况；
  - `--only` 合并结果；
  - 缺运行器、缺文件、超时；
  - 路径注入、路径越界、最长后缀匹配；
  - 只有条目的节点算进行中。
- **token 与钩子（13 个）**：
  - 去重与统计口径；
  - 增量记录与切换模块；
  - 未归属；
  - 会话记录读不到；
  - 上下文摘要；
  - 三个钩子各自的行为；
  - 未初始化项目里静默；
  - 坏输入不报错。
- **终端确认（5 个）**：AI 无终端被拒、`--by human` 也被拒、人看到条目后按 y 锁定、非 y 一律取消、多节点全有或全无；外加伪造锁会被标为待复核。
- **审查加固（14 个）**：三种模板下的路径注入、`-` 开头的路径、改 runner 触发待复核、重复文件、实时待复核、信任机制、`.gitignore`、子目录查找、后台失败写日志、坏流水容错、上下文围栏、重复记账。

此外，我用打包后的 `pm.mjs` 在临时项目里做了两轮端到端演练，全部符合预期：

- 第一轮：初始化 → 开工 → 锁定 → 测试先失败 → Stop 记 token → SessionEnd 在 0.08 秒内返回、后台完成验收 → 改动测试后变为待复核 → 新会话注入摘要。
- 第二轮（加固后）：从子目录触发钩子 → 未信任时不跑验收 → `pm trust` 后跑验收 → 带引号模板下的路径注入被挡住。

## 9. 已知局限

- 还没有在真实安装的插件里，让 AI 从头完整走一遍阶段一和阶段二。Skill 的指令效果要在真实使用中观察和调整。
- 验收结果按文件计数（一个文件算一条），不解析测试框架内部的用例数。
- 只支持 macOS / Linux 的 shell 引号规则，Windows 未测试。
