# P1 · 生成 `.pm/dashboard.html` 五视图

> 配套图形版：[p1-dashboard.html](p1-dashboard.html)（内嵌了真实生成的页面）· 引擎见 [p0-engine.md](p0-engine.md)

## 1. 用法

```bash
npm run pm -- dashboard
```

默认读取当前目录下的 `.pm/`，写出 `.pm/dashboard.html`。可选参数：

| 参数 | 作用 | 默认 |
|---|---|---|
| `--dir <目录>` | `pm.yaml` 所在目录 | `.pm` |
| `--out <文件>` | 输出路径 | `<dir>/dashboard.html` |
| `--now <ISO 时间>` | 计算"已进行天数"的基准时间 | 当前时间 |

输入文件：

| 文件 | 是否必需 | 缺失时 |
|---|---|---|
| `pm.yaml` | 必需 | 报错，退出码 1 |
| `evidence.json` | 可选 | 所有节点按"没有验收结果"处理 |
| `ledger.jsonl` | 可选 | 成本视图显示空状态 |

退出码：0 成功，1 输入有误（会列出具体错误），2 命令或参数用法错误。警告（比如验收结果里有未知节点）打到 stderr，但不阻止生成。

示例项目：

```bash
npm run demo:dashboard
```

会生成 `examples/kb-demo/.pm/dashboard.html`，并复制一份到 `docs/assets/demo-dashboard.html`。

## 2. 生成的页面

一个文件，约 58 KB，不依赖网络：

- CSS、JS、数据全部内嵌；
- 不加载外部字体，用系统字体；
- 双击即可打开，可以直接发给别人。

页面结构：

| 区块 | 内容 | 交互 |
|---|---|---|
| 页头 | 项目名、生成时间、建成度与生效度两个环 | — |
| ① 架构地图 | 功能 / 逻辑 / 物理三张图。逻辑图按分层排列；功能图和物理图按依赖深度排列，被依赖的在下面 | 切换视图；切换"建成 / 生效"视角；点击模块高亮上下游，右侧面板显示依赖、被依赖、跨视图映射、所属目标、成本、根因阻塞 |
| ② 依赖与阻塞 | 哪些未完成模块卡住了最多已写好的模块；卡住同一组模块的根因合并为一条链 | 点击跳到地图 |
| ③ 目标与下一步 | 每个目标的进度环、"还要建"和"已建被卡住"；按杠杆排序的前 8 条推荐；第一条推荐的 what-if | 点击模块跳到地图 |
| ④ 成本 | 时间 × token 气泡图、卡住预警线、沉没成本、按状态和按目标的分布 | 点击气泡跳到地图 |
| ⑤ 旅程蓝图 | 每个声明了旅程的目标一张：泳道、可见线、可用性曲线、切线、红色断点线 | 点击模块跳到地图 |

任何视图出错只影响它自己：其他视图照常显示，出错的地方显示红色提示。

## 3. 安全

`pm.yaml` 里的名字可能来自 AI 或第三方，按不可信内容处理：

- 数据放在 `<script type="application/json">` 里，序列化时转义 `<` 和 JS 行分隔符，名字里写 `</script>` 也无法跳出。
- `<title>` 里的项目名做了 HTML 转义。
- 浏览器端只用 `textContent` 和 `setAttribute` 写入内容，没有 `innerHTML`。
- 页面带 Content-Security-Policy：只放行本页那一段脚本（按哈希），其他内联或外部脚本一律拦截。我在浏览器里试过往页面注入脚本，被拦住了。
- 测试里专门放了带 `<img onerror>` 的恶意名字，确认它只会显示成文字。
- 命令行输出前会去掉终端控制字符：YAML 报错时带出的源码片段里，可能夹着能操纵终端的转义序列。

## 4. 代码结构

| 文件 | 职责 |
|---|---|
| `src/cli.ts` | 命令行：解析参数、读取输入、调用 `analyze()` 和 `renderDashboard()` |
| `src/dashboard/render.ts` | 拼装单文件 HTML，负责转义 |
| `src/dashboard/client/dashboard.css` | 样式（含深色模式、窄屏、减少动效） |
| `src/dashboard/client/util.js` | DOM 与 SVG 工具、状态配色、读取内嵌数据 |
| `src/dashboard/client/map.js` | ① 架构地图与详情面板 |
| `src/dashboard/client/blockers.js` | ② 依赖与阻塞 |
| `src/dashboard/client/goals.js` | ③ 目标、推荐、what-if |
| `src/dashboard/client/cost.js` | ④ 成本 |
| `src/dashboard/client/blueprint.js` | ⑤ 旅程蓝图 |
| `src/dashboard/client/main.js` | 入口：页头、交互绑定、逐个视图渲染与出错隔离 |

`analyze()` 的输出为此补充了三项：依赖与映射的边列表、每个节点所属的目标、`settings`（卡住天数阈值等），另外加了生成时间。

## 5. 测试

共 76 个测试，类型检查通过。新增 23 个：

- **渲染（6 个）**：完整文档结构、内嵌数据可还原、不引用外部资源、恶意名字被转义、行分隔符转义、CSP 哈希与脚本一致。
- **CLI（9 个）**：
  - 正常生成；
  - `evidence.json` 和 `ledger.jsonl` 可缺省；
  - 自定义目录和输出路径；
  - 缺少 `pm.yaml`、`pm.yaml` 无效、验收结果不合法；
  - 警告不阻止生成；
  - 输出里去掉终端控制字符；
  - 用法错误。
- **页面冒烟（7 个）**：用 happy-dom 真正执行页面脚本，检查：
  - 五个区块都能渲染；
  - 三个视图切换；
  - 建成和生效视角切换后，节点状态随之变化；
  - 点击模块后面板列出根因；
  - 用键盘选中模块后，焦点仍留在该模块上；
  - 恶意名字只显示成文字；
  - 全新项目的各种空状态。
- **analyze 扩展（1 个）**：边、目标归属、设置。

我还在浏览器里看过生成的页面，宽屏和手机宽度都没有横向溢出。

## 6. 代码审查

独立安全审查：没有 CRITICAL / HIGH 问题，XSS 链路干净。已处理：

| 问题 | 处理 |
|---|---|
| 键盘选中模块后重绘，焦点丢到页面顶部（MEDIUM） | 重绘后找回原节点并聚焦；跳转后聚焦目标节点 |
| 终端输出可能带出控制字符（LOW） | 输出前过滤 |
| 平滑滚动不遵守"减少动效"设置（LOW） | 检测系统设置 |
| 推荐条长度理论上可能除零（LOW，当前不可达） | 加下限保护 |
| 建议加纵深防御（INFO） | 加了基于哈希的 CSP |

"目标 `requires` 为空导致 0/0"那条不需要改：schema 已经要求至少一项。

## 7. 已知局限

- 地图用的是固定的分层排版，没有做交叉最小化，依赖多时连线会交叉。节点多时可以考虑引入专门的图布局算法。
- 页面是静态快照，要看最新状态就得重新运行命令生成。P2 会在会话结束时自动运行。
