# 产品形态与愿景

> 配套图形版：[product-vision.html](product-vision.html) · 方法论见 [concept.md](concept.md)

## 1. 目的

AI 让一个人能同时推进多个项目，每个项目的规模也越来越大，但人的思考带宽没有变。很多人已经同时在做 3–5 个项目，靠记忆和列表早就管不过来了。

这个产品要帮所有用 AI 开发的人做到三件事：

1. **看清**：每个项目的全貌、哪里已生效、哪里被卡住。
2. **找到差距**：离每个目标还差什么，投入是否花在了刀刃上。
3. **更好地行动**：下一步做哪件事对目标的推动最大，以及做完之后目标会怎样变化。

## 2. 核心形态：一个随项目而生的 Skill / 插件

它不是一个需要人记得去打开的工具，而是**嵌在开发流程里**：

| 时机 | 它做什么 |
|---|---|
| 项目开始 | 介入并说明需要哪些管理；和人一起确认目标；扫描仓库生成三套架构草图；在项目里初始化 `.pm/` |
| 每个功能开工 | 声明当前模块；起草验收条目（功能层请人确认）；开始计时 |
| 每次会话结束 | 运行验收测试 → 更新状态；记录本次 token 用量；重新计算生效 / 缺口 / 杠杆；刷新页面 |
| 每次会话开始 | 把"目标缺口 + 推荐下一步"作为上下文交给 AI |

## 3. 两种部署形态

### 形态 A：本地（每个项目自带一个"管理小项目"）

```
my-project/
└── .pm/
    ├── pm.yaml            # 目标、三套架构、依赖、映射
    ├── acceptance/        # Gherkin 验收条目（*.feature）
    ├── ledger.jsonl       # 每次会话的时间、token、测试结果流水
    └── dashboard.html     # 单文件五视图，本地直接打开
```

- 零依赖、离线可用，`.pm/` 随代码一起进 git，历史可追溯。
- 适合个人、单项目、对隐私敏感的场景。

### 形态 B：云端（账号下的项目组合）

- 用户开一个账号；Skill 在新项目初始化时自动把项目注册到账号下，并生成该项目的页面。
- 云端多一个**多项目总览**：所有项目的生效度、目标缺口、token 消耗、卡住预警放在一页，按"最需要你关注"排序。
- **只同步元数据**（`pm.yaml`、状态、测试结果摘要、成本流水），不上传源代码。
- 适合同时做多个项目、需要在手机或其他设备上查看、或者团队协作的场景。

### 关系：本地优先，云端可选

本地形态是完整可用的；云端是在本地之上加一条同步通道。断网或不开账号，本地照常工作。

## 4. 多项目总览（云端核心页面）

每个项目一张卡片：

- 缩略架构图（颜色即状态）
- 生效度环 + 建成度对比
- 各目标进度与最大缺口
- 近 7 天 token 消耗趋势
- 卡住预警 / 待复核提示

排序依据"需要关注度"：卡住预警、待复核、沉没风险高、目标长期无进展的项目排在前面。顶部给出跨项目的"今天最值得做的三件事"。

## 5. 路线

| 阶段 | 内容 | 形态 |
|---|---|---|
| P0 | `pm.yaml` schema + 计算引擎 | 库 |
| P1 | 生成 `dashboard.html` 五视图 | 本地 |
| P2 | Skill：项目初始化、功能开工、会话结束三个钩子 | 本地 |
| P3 | Claude Code 常驻面板 | 本地 |
| P4 | 账号、自动注册、单项目页、多项目总览 | 云端 |

## 6. 待讨论

- 支持哪些 AI 编码工具？Claude Code 优先；Codex 等其他工具需要各自的钩子和 token 统计接口。
- 云端多项目总览是否允许跨项目的目标（比如"一季度上线两个产品"）？
- 团队场景下，功能层验收条目由谁确认（产品负责人还是开发者）？
