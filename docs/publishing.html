ai-pm · 定位与发布

一个装进 AI 代理
的项目管理插件

品类是代理插件：技能、钩子、斜杠命令，加上随插件安装的命令行 pm 和一张离线的项目地图。仓库本身就是插件市场，推到 GitHub 就是发布。

01

对外怎么说

一句话讲清品类和价值；再用"它不是什么"挡掉常见误解。

给 AI 编码代理用的项目管理插件——用架构图看进度，用验收测试判断完成，从目标倒推下一步。

用 Claude Code、Codex 写代码时，项目会被 AI 迅速放大，任务列表和看板跟不上。ai-pm 把项目画成功能、逻辑、物理三张架构图，只按验收测试判断"做完"，区分"已建成"和"真正生效"，从目标倒推出杠杆最大的下一步，并按提交回看项目的演进。

02

发布到哪里

按推荐顺序。① 是主渠道：仓库根目录已有 .claude-plugin/marketplace.json，推送即发布，没有审核。

1

GitHub 公开仓库

仓库就是插件市场。Claude Code（终端、桌面应用、VS Code）和 Codex 都能直接装。

claude plugin marketplace add 组织/仓库 claude plugin install ai-pm@ai-pm
2

Anthropic 插件目录

在 claude.ai/directory 被搜索到。门户提交，需付费计划；先用 claude plugin validate --strict 自检。

claude.ai/directory/manage

⚠ 顶层 bin/ 会被 claude.ai 拒装，上架前要挪位置

3

Releases + 标签

每次发布打标签、写更新说明；用户可以固定版本。

…marketplace add 组织/仓库#v0.3.0
4

npm（以后）

给 OpenCode、DeepSeek Harness 用户省掉 git clone 和构建。需加 bin、files，确认包名可用。

npx <包名> setup opencode
03

发布前清单

绿点已完成，红圈还没做，橙圈视情况而定。现在用户两条命令就能装上。

  • 仓库改为公开wMango/ai-pm
  • 选许可证，加 LICENSE，plugin.json 写 licenseMIT
  • 市场改正式名：ai-pm-local → ai-pm，同步文档里的安装命令ai-pm@ai-pm
  • plugin.json 补 homepage、repository、author、keywords已补齐
  • 每次发布递增 plugin.json 的 version，marketplace 条目里不写当前 0.3.0
  • 运行 claude plugin validate ./plugin --strict已通过
  • 合并进 main，打标签，写 Release 说明v0.3.0
  • 换一台机器从零安装、初始化、开工走一遍真实验证
  • 决定本仓库自己的 .pm/ 是否随仓库公开公开，作为示例
  • （只为上架目录）把 plugin/bin/ 挪出顶层 bin/同步钩子与技能路径
已核实的风险：官方文档说明 claude.ai 和 Cowork 不会安装带顶层 bin/ 的插件。终端版和桌面应用的 Code 标签页不受影响；只在上架 Anthropic 目录时需要处理。审核标准与时长尚未核实。
04

发布之后，用户怎么更新

只有版本号变了，用户才会拿到新版本；第三方市场默认不自动更新。
